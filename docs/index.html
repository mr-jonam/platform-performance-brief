The decision in focus

What demand assumption and user outcome need evidence before discussing a performance engagement?

Product owners, platform owners and performance stakeholders clarifying expected demand before planning performance work.

An orientation resource for a focused first conversation. Results reflect your answers and assumptions, not observed system behaviour.

What you can take away

  • Distinguish active people, business transactions and HTTP requests.
  • Understand why average transaction demand is not peak concurrency or capacity.
  • Create a performance discussion brief with assumptions and unresolved evidence questions.

Before you use this guide

Does the calculator estimate capacity or concurrent users?

No. It computes an average transaction rate from entered assumptions. It does not measure or predict system behaviour.

Can I use this to run a load test against SAP or another SaaS?

No. No test runner or traffic generator is included. Execution requires a separately authorised scope and current provider conditions.
